# 首轮结果：尚无整体优势，找到一个可追查的压缩失败机制

2026-09-14，使用项目配置的 `deepseek-v4-pro` 完成 36 题主实验及 36 题原文消融。
当前证据不支持“版本恢复整体优于普通检索”的结论；消融发现一例局部约束更新导致摘要丢失其他约束、
随后被原始证据修复的案例，值得用更真实的任务继续检验。

## 主实验

| 方法 | 精确匹配全部设置 | 正确值且证据正确的字段 | 旧值复活 | 管线失败 |
|---|---:|---:|---:|---:|
| 普通滚动摘要 | 29/36 | 96/108 | 0 | 1 |
| 摘要 + BM25 原文检索 | 30/36 | 95/108 | 0 | 0 |
| 摘要 + 版本筛选 + 原文 | 30/36 | 99/108 | 0 | 0 |

版本恢复相对普通检索为 **0 胜、0 负、36 平**；相对普通摘要为 2 胜、1 负、33 平。
不能把 30/36 对 29/36 直接解释成约束保持能力提升。

逐条后验检查发现：27 个字段的值不匹配是连字符/空格、大小写、单位缩写或携带字段名等表达差异，
没有发现这些回答选用了已废弃设置。另有一题普通摘要达到 512 输出 token 上限，按预定规则拒绝继续，
形成三个无答案字段；该次截断仍计入用量和失败分母。
这些检查是 **Codex 的后验审阅，未经独立人类标注**，没有替换精确匹配分数或修改 gold。

另一个较具体的观察是：普通检索在 `pagination-proposal` 和 `date-parser-log` 两题中，
把四个未改动字段错误引用到只更新另一字段的 `e06`，其真正来源是 `e01`。
共享小摘要把多字段归并到了同一个更新事件；检索组最终提示已经包含正确原文，却仍沿用错误引用。
版本恢复修正了这四处来源。这是两个案例的来源追踪信号，尚非普遍收益。

## 原文消融

另开一次实验，保持相同任务、预算和模型；两组共享新生成的同一份小摘要。
一组保留当前版本的原始正文，另一组仅保留字段、确认状态和事件 ID，去掉原文。
不能把这次 versioned 的 31/36 与主实验的 30/36 混成同一次采样结果。

| 方法 | 精确匹配全部设置 | 正确值且证据正确的字段 |
|---|---:|---:|
| 版本头 + 原文 | 31/36 | 101/108 |
| 版本头，不含原文 | 30/36 | 97/108 |

保留原文为 **1 胜、0 负、35 平**，无 API 或输出截断失败。

唯一多通过的题目是 `reverted_decision/stylesheet-strategy`，有可追查的实质差异：

1. 用户在 `e01` 指定 `styling=css-modules`、`theme=system`、`motion=reduced-aware`。
2. 后续只修改、再撤回 `styling`，其他两字段没有改变。
3. 小摘要在第二次压缩中把整个 `e01` 当成被 `e06` 取代，最终摘要丢掉 `theme` 与 `motion`。
4. 无原文组虽然仍持有这两字段指向 `e01` 的正确版本头，却只能回答 `unknown`。
5. 原文组读取 `e01` 正文后恢复 `system` 和 `reduced-aware`。

这一案例支持进一步研究“局部更新被摘要误当成整体失效”的失败机制。
它只有一个任务样本；显式版本头仍由输入协议提供，尚未检验从普通自然对话抽取这种生命周期的能力。

关闭版本筛选的 `no_versions` 在全部 36 题、相同摘要下与 `retrieval` 的输入逐字节一致，
因此主实验检索组已经是对应对照，没有为相同输入重复付费采样。

## 这次实验能说明什么

**目前不能支撑一篇强调任务能力提升的方法论文。** 主实验有效对照打平，精确匹配又受到表达形式影响。
现有观察更适合用于定位下一轮实验：测试字段级约束更新与证据来源，而不是先扩建完整记忆系统。

下一轮应优先修正评测对象：使用可执行的配置/行为检查，或让各组从相同公开选项 ID 中选择，
将真正的约束错误与字符串写法分开。随后从真实长任务中收集局部修改、部分撤回和压缩后的失败轨迹，
冻结一批独立任务，再检验这个单案例是否重复出现。
若使用这次失败案例构建新任务，它们属于开发集，不能再作为独立验证集宣传。

本轮没有修改原评分、追选获胜样本、修改线上 Agent runtime 或声称统计显著性。
数据只有 36 个合成任务，六类布局较规则；单模型单次、相同 UTF-8 字节上限也不等于严格同 token 比较。
